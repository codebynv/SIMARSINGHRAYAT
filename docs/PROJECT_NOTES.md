# Project Notes

Keep project-specific notes here so implementation decisions remain easy to revisit.

## Change discipline

- Keep changes focused.
- Prefer small, reviewable commits.
- Document non-obvious behavior.
- Avoid committing generated files or local configuration.

## Before submitting work

- Verify the application starts correctly.
- Exercise the changed functionality.
- Check for accidental secrets or debug output.
- Update documentation when the project structure changes.

## Git convention

Use concise messages that describe the intent:

- `feat: add ...`
- `fix: correct ...`
- `docs: update ...`
- `chore: maintain ...`
